# Maintenance

Connor Beleznay, [@Connorbelez](https://github.com/Connorbelez), is the initial maintainer. This repository is open to contributors; it does not yet have a multi-maintainer team or a guaranteed response time.

Changes go through pull requests and required CI. A maintainer reviews source provenance, behavior, compatibility, and relevant hardware evidence. Do not infer hardware support from a passing source or host test. Tagged releases require the gates in `ROADMAP.md`; until then, `main` is experimental. Record the exact tested revision and versions in each release.

Review incoming issues and upstream changes at least monthly when actively maintaining a release. If upkeep stops, publish the status and invite a successor rather than leaving support claims unchanged.

License scope: MIT. Preserve imported notices. AI-assisted changes must disclose their use and remain compatible with the receiving upstream project's contribution rules.
